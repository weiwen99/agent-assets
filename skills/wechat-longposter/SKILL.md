# 手机长图海报

把一份已核实的结论做成一张可直接发微信群的竖版 PNG。模板、渲染器与验收标准都在本技能内；各次任务只换内容和信息取舍，不换视觉语言。

## 前置

- 收集事实：数字、单位、时间点、采集方法、来源。缺数据先向用户要。
- 确认用途与披露范围：群内速读、汇报留档还是对外发布；对外发布时去掉内部主机名、序列号、IP。
- 确认输出位置。图片不写回模板仓库。

## 步骤

### 1. 定稿一句话结论与三个数字

先写三行：

1. **一句话结论**：正常、异常或待观察，以及要不要处理。
2. **三个关键数字**：不往下滑也能记住的三个值。
3. **证据分组**：支撑结论的主题，每组只回答一个问题。

摘要与详情是总—分关系：概览区放结论和三个数字，详情区展开证据；同一事实只保留一个位置，摘要不复述详情。
完成条件：每个数字都有来源和单位；首屏（约前 1400 px）能独立说明结论；没有编造的评分、百分比或预测寿命。

### 2. 选版式骨架

以 [模板](assets/poster.html) 为起点，默认顺序：

1. 深色 Hero：对象身份、结论徽章、日期。
2. 三列关键数字。
3. 证据卡片：一张卡片一个主题，一个主题一种呈现方式。
4. 深色结论卡：三条可转述的话。
5. 页脚：来源、采集时间、方法。

画布固定宽 1080 px，高由内容决定，常见 1:3–1:5。内容不足时输出短图，不用空白硬撑。模板以设备健康报告为例；其他主题替换标题与字段名，保留层级和节奏。
完成条件：顺序与模板一致，或每处差异都有理由；没有与结论无关的模块。

### 3. 替换文案与数据

复制模板，替换所有占位内容。颜色、字号、圆角、间距沿用模板的 `:root` 与既有类；需要新样式时先复用现有类，确实新增时保持同一套 token。

- 字体栈与字号层级沿用模板；数字加 `tabular-nums`，值不换行。
- 中文标题手动断行，避免行末孤字；说明文字控制在 1–2 行。
- 比例类数据用真实比例的进度条；接近 0 的值保留最小可见宽度，量级不变。
- 语义色固定：绿=健康，琥珀=风险，红=故障；主色只做引导。
- 只引用本地资源。

完成条件：1080 px 宽度下无横向溢出；所有占位文案已替换；语义色只出现在对应状态；百分比与进度条同源。

### 4. 渲染 PNG

```bash
node scripts/render.mjs assets/poster.html /tmp/poster.png
```

渲染器需要 Node 22+（内置 WebSocket/fetch），用 Chrome headless + CDP 测量 `scrollHeight`，按精确高度截图，输出 1080 px 宽的 sRGB PNG。Chrome 不在默认路径时用 `--chrome` 或 `CHROME_BIN` 指定。

完成条件：命令成功；输出 PNG 的宽度为 1080 px，高度等于测得的内容高度。

### 5. 验收

打开渲染结果，逐项检查：

- 首屏是否包含结论和三个关键数字。
- 是否有文字被裁切、溢出卡片或行末孤字。
- 数字、单位、日期是否与来源一致；百分比与进度条是否同源。
- 语义色是否只用于状态。
- 页脚是否写明来源、采集时间与方法。
- 文件是否能在普通图片查看器中打开，大小尽量低于 2 MB。

完成条件：每项都有明确结果；发现问题就改文案或模板后重渲染，不以“看起来差不多”交付。

## 边界

- 一张图只回答一个问题；复杂关系留给正文或表格。
- 未验证的推测不写成结论；必须保留的不确定性放页脚或注释。
- 模板与渲染器不绑定具体主题；版本号、主机名、序列号等由当前任务提供。
