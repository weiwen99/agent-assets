# Org-mode 行内标记空格约束

生成 Emacs org-mode 文档（`.org` 文件或任何 org 语法文本）时，行内标记必须遵守边界空格约束。本规范覆盖两类标记：原文/代码标记 `=text=` 与强调标记（`*bold*`、`/italic/`、`_underline_`、`+strike+`、`~code~`）。

## 通用原则

- 标记**内侧**紧贴内容（`=text=`，不是 `= text =`）。
- 标记**外侧**必须各紧邻一个半角空格（U+0020，不是全角空格 `　`，也不是不换行空格）；或位于行首/行尾。
- 无论旁边是中文、半角标点（`,.`）还是全角标点（`，。、`），外侧空格都不能省略。
- 原因：org-mode 只允许标记边界是空白或极少数允许字符；中文与标点不在允许集合内，任何一侧紧贴都会导致标记被当作普通文本。

## `=code=` 标记

唯一正确写法：

`今天是 =一个= 晴天`

以下写法一律禁止（两侧只要有一侧紧贴，渲染就不符合预期）：

- `今天是=一个=晴天`
- `今天是=一个= 晴天`
- `今天是 =一个=晴天`
- `今天是=一个=,晴天`
- `今天是，=一个=晴天`
- `今天是，=一个=。晴天`
- `今天是一个=晴天=。`

## 强调标记（`*bold*` 等）同款边界约束

强调标记与 `=code=` 遵守完全相同的边界规则：内侧紧贴、外侧空白。与中文或标点紧贴即失效：

- 错误：`是**只读**的`、`（**已处理**）`、`**空（默认）**：`
- 正确：`是 **只读** 的`、`（ **已处理** ）`

## 本次教训总结（2026-08-20 新增，三类高频违规）

1. **开标记左侧紧贴标点**：`：=X=`、`，=X=`、`（=X=`、`；=X=`、`、=X=` 都是错的 → 必须 `： =X=`、`， =X=`、`（ =X=`。
2. **标记内容与 `=` 之间误留空格**：`= X =`、`=X =` 都是错的 → 必须 `=X=`。
3. **闭标记右侧紧贴标点**：`=X=` 直接跟 `，`/`。`/`、`/`）`/`（`/`；`/`：` 都是错的 → 必须 `=X= ，`、`=X= ）` 等。

## 禁止事项

- 禁止用 `**bold**` 伪装标题（如 `**.git 例外**`）→ 用真正的标题行 `* 标题`、`** 标题`、`*** 标题`。
- 禁止在 org 文档中混用 Markdown backtick 当代码标记 → org 的代码标记是 `=code=`。
- 不确定强调边界是否正确时，宁可不用强调，改用 `=code=` 标记或纯文本。

## 验收步骤

生成或修改任何 org 文本（`.org` 文件、聊天里的 org 片段、commit message 里的 org 语法）后，发送或提交前按顺序执行：

1. **配对扫描。** 逐行从行首向右配对标记（跳过 `#+BEGIN_SRC`/`#+BEGIN_EXAMPLE` 块与 `#+` 行）：开标记左侧必须是行首或一个半角空格，闭标记右侧必须是行尾或一个半角空格。`=a= =b=` 合法；`甲=a= 乙`、`=a=乙` 不合法。
2. **内侧扫描。** 每对标记之间不得出现首尾空格：`= a=`、`=a =`、`= a =` 都判失败。
3. **强调同规。** 对 `*bold*`、`/italic/`、`_underline_`、`+strike+`、`~code~` 重复第 1–2 条，判定标准与 `=code=` 相同。
4. **渲染确认。** 有 Emacs 时用 `emacs file.org` 打开：标记应按 org 语法着色，而不是被当作普通字符。纯聊天输出无法渲染时，以第 1–3 条为通过标准。
5. **零例外交付。** 任一失败改到通过再交付；不确定时按「禁止事项」最后一条降级为 `=code=` 或纯文本。
